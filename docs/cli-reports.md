# Машиночитаемые отчёты CLI

Для сборки с проверкой опечаток используйте `python3 scripts/gost_docx.py build task.json report.docx --strict`. Проверка выполняется до записи результата: неизвестное поле приводит к ошибке, существующий DOCX сохраняется. Набор разрешённых полей совпадает с `validate --strict`.

Для интеграции с агентами и автоматическими проверками доступны команды:

```bash
python3 scripts/gost_docx.py doctor --json
python3 scripts/gost_docx.py validate task.json --json
python3 scripts/gost_docx.py validate task.json --strict --json
python3 scripts/gost_docx.py audit report.docx --json --out audit.json
```

Команды выводят один JSON-объект в stdout с `schema_version: 1` и булевым `ok`. Код завершения — 0 при успехе и 1 при обнаруженной проблеме. Аудит возвращает 2, если документ не удалось проверить. Без `--json` сохраняется текстовый вывод. Ошибки использования CLI, например пропущенные аргументы, выводятся обычной справкой в stderr.

`validate --strict` дополнительно отклоняет неизвестные поля на верхнем уровне и внутри реферата, глав, подразделов, источников и приложений. По умолчанию дополнительные поля разрешены для совместимости; генератор их не использует.

`audit --json` возвращает `completed`, массив `findings` с полями `severity` (`error` или `warning`), `location`, `message`, а также массив `errors` для ошибок выполнения. При `completed: false` отсутствие замечаний не означает успешную проверку. Предупреждения не меняют успешный код завершения. `--out` сохраняет тот же JSON после завершённого аудита. При невозможности проверить документ диагностический JSON выводится только в stdout, существующий файл отчёта остаётся прежним.

Для справки доступны `audit --help`, `format --help` и `build --help`, в том числе без установленных зависимостей. `build` отклоняет результат, указывающий на исходное JSON-задание, включая символические и жёсткие ссылки.

`doctor` возвращает массив `checks`. Каждая запись содержит `name`, `status` (`ok`, `missing`, `skipped` или `error`) и `hint`. Проверка пакета `docx` пропускается при отсутствии Node.js. Подсказка для успешной проверки равна `null`. На запуск проверки пакета отводится 10 секунд. Превышение времени или невозможность запустить Node.js дают статус `error`, подсказку и код завершения 1.

`validate` возвращает массив `errors` с полем `message`. При успехе массив пуст. При ошибке возвращается первая обнаруженная проблема: чтение файла, синтаксис JSON, структура задания или отсутствие Node.js. Текст сообщения предназначен для показа пользователю, его формат не является отдельным программным контрактом.

Для строгой приёмки в CI используйте `audit report.docx --fail-on-warning --json`. Тогда предупреждения также дают код 1 и `ok: false`, сохраняя уровень `warning` в отчёте. Без этого параметра предупреждения не меняют код завершения. Невозможность проверить документ по-прежнему даёт код 2.

Проверка задания не создаёт DOCX и не требует пакета `docx`. Успешная проверка подтверждает структуру входа, но не достоверность содержания и не готовность всех зависимостей для генерации. Используйте `doctor` для проверки окружения.
