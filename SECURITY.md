# Политика безопасности

## Сообщение об уязвимости

Не публикуйте сведения об уязвимости в открытом issue. Отправьте описание через private vulnerability reporting в GitHub repository или свяжитесь с владельцами репозитория через профиль организации `optMD`.

В сообщении укажите:

- затронутую версию или commit;
- минимальный способ воспроизведения;
- ожидаемое и фактическое поведение;
- потенциальное влияние;
- безопасный способ связаться с вами для уточнений.

Не прикладывайте реальные документы с персональными данными, коммерческой тайной или другой чувствительной информацией.

## Область безопасности

Проект обрабатывает пользовательские `.docx` локально. Перед обработкой неизвестных файлов используйте изолированное окружение и не запускайте макросы или встроенные внешние ссылки из документов.
